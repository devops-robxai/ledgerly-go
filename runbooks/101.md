Copy a prompt into Cursor. Review every result. Port **43173**.

## 1. What is Cursor? — Ask → Plan → Agent → Debug

### Ask

```text
/ask Tell me what this Ledgerly Go app does in 3 sentences. Cite cmd/server/main.go and internal/billing/.
```

```text
What are Ledgerly's only plan prices, and which seeded invoices are overdue? Cite internal/billing/plans.go and internal/billing/seed.go.
```

```text
Explain the suggested-credit flow end to end. What is intentionally wrong on a clean tree? Cite internal/billing/suggested_credit.go, the v1/v2 HTTP handlers, and the dispute detail page. Do not edit any files.
```

### Plan

Invoice detail (`/invoices/inv_1048`) shows the customer email as **read-only text**. There is no update form and no write path — Plan→Agent builds that feature from scratch.

```text
/plan I want a feature to update the customer email on the invoice detail customer card. Don’t implement email validation — keep the POST form simple. Add the form in web/templates/invoice_detail.html, handle POST /invoices/{id}/email in internal/http/handlers.go, and persist with a store method in internal/billing/store.go.
```

### Build in Agent mode

Build the plan locally. Check **http://localhost:43173/invoices/inv_1048** — customer email starts as read-only (no form). After the agent implements it, change the email, save, and confirm the page shows the new value.

### Debug

```text
/debug the failing test
```

Expect the agent to find `TestSuggestedCreditUsesV2Cap` and the v1 client constant.

### Fix

```text
Diagnose why dsp_1043 shows a $400 suggested credit even though v2 caps it at $249. Switch SUGGESTED_CREDIT_API_VERSION from v1 to v2 in internal/billing/suggested_credit.go. Preserve both API routes, the $400 dispute claim, and internal/billing/suggested_credit_test.go. Run go test ./... and verify /disputes/dsp_1043 shows $249.00.
```

### Guardrail rule

```text
/create-rule Future code must never call /api/v1/disputes/*/suggested-credit. It must use /api/v2/disputes/*/suggested-credit. Create the project rule at .cursor/rules/suggested-credit-api-v2.mdc and show me the file before I keep it.
```

## 2. How do I work with an agent?

### Run Mode allowlist

Settings → Agents → Executions & Approvals → Run Mode → Allowlist. Allow `go test` / `go run` as needed.

### Verify email feature

After Plan→Agent: open http://localhost:43173/invoices/inv_1048 — Customer card should now have an email form. Save a new address and confirm it persists on reload.

### Redact (steer / stop / continue)

```text
Redact the customer email in the UI. The first two characters and domain are plaintext. When I click to type in the box, clear it and save the new email.
```

Stop mid-flight, steer, review diffs, restore from a checkpoint as needed.
