## Beat 5. Hooks, teaching (18–22, S11–S14)

They already have rules and skills from the 101. Hooks are how you enforce a standard the agent cannot skip.

Hooks are commands in `.cursor/hooks.json`. Each script reads a JSON event on stdin and writes a JSON decision on stdout. Permission hooks return `allow`, `deny`, or `ask`. Exit code 2 is also a deny. Any deny wins over ask, and ask wins over allow.

Four events on the slide: `beforeShellExecution`, `beforeMCPExecution`, `afterFileEdit`, `beforeSubmitPrompt`.

Scopes: project (`.cursor/hooks.json`, shared in the repo), user (`~/.cursor/hooks.json`), and team or enterprise (dashboard). Team-wide hooks from the dashboard need an Enterprise plan. Do not promise that Betsson has it.

The CoE angle: a `beforeMCPExecution` hook that checks the server name against an allowlist, the same idea as 30 team allowlists feeding one baseline.

## Beat 9. Parallelize, teaching (38–42, S21–S26)

Three ways to split work.

Pipeline: agent 1, then 2, then 3. Dependent steps. Pass context with @Chat.

Coordinator: you review the outcome. A coordinator plans; subagents work in parallel (data, API, UI), each with its own context window, editing independently.

`/multitask` runs asynchronous subagents on their own worktrees and orchestrates state. `/create-subagent` is how you add a specialist (build, review, test). A new agent by itself is right when the task is already well defined.

Let Auto pick each subagent's model (cost vs intelligence). The org or team defines the available models. The CoE may be the group that decides that here; do not state it as a fact if it is still unconfirmed.

After it finishes: audit the git diff, audit the worktrees, run tests and linters, review cross-agent conflicts.
